# weekly-sales-report

このスキルの仕事は、weekly-sales-report の作業の画面（Web管理画面。ブラウザーで開く画面）を用意し、その URL をユーザーに渡すことである。作業そのものは、ユーザーが画面で設定して開始ボタンを押した後に、weekly-sales-report の統括・作業・検証のエージェントが行う。

## 先頭の決まり

次の決まりは、このスキルを使った手番だけでなく、その後の手番（実行の終わりの知らせを受けた手番を含む）でも守る。

1. weekly-sales-report の作業を、自分でしない。作業のためにファイルを書く、コマンドを動かす、`task` で weekly-sales-report のエージェント（`weekly-sales-report:orchestrator`、`weekly-sales-report:worker` など）を呼ぶ、動いている weekly-sales-report のエージェントにメッセージを送る（`write_agent` など）、のどれもしない。画面から始めた作業だけが、ユーザーの選んだモデルと設定で動き、画面で見守って止められるためである。
2. 作業の中身を聞き返さずに、すぐ `weekly-sales-report_open` を呼ぶ。作業ごとの設定（対象や条件など）は、ユーザーが画面で入れるためである。
3. 画面でできること（実行の様子や結果を見る、実行を止める、Issue の案を承認して起票する）を頼まれたら、画面で行うよう伝え、チャットで代わりに行わない。画面から止めるとこの実行のエージェントだけが確実に止まり、承認した案だけが起票されるためである。
4. 日本語で応答する。ユーザーが別の言語で書いたら、その言語で応答する。画面と README が日本語で書かれているためである。

## このプラグインがする作業

毎週の売上データ（CSV）から、部長に出す週報を作る（K-01）。部長が週報を何に使うかは分かっていない（K-01）。入力は毎週の売上データ（CSV）である（K-02）。週報は Word ではなく、メールにそのまま貼れる Markdown のファイル weekly_report.md にする（K-17）。プラグインは weekly_report.md を作るところまでをし、部長に出す（メールに貼って送る）のは本人がする（K-22）。

## 作業を頼まれたとき

1. `weekly-sales-report_open` を呼ぶ。`requestText` には、ユーザーが頼んだ作業の文を、要約せずにユーザーの言葉のまま渡す。統括エージェントへの指示に、そのまま入るためである。
   - 失敗が返ったときは、返った理由を伝えて、手番を終える。理由に英語のエラーの文や専門用語が入っていたら、何が起きたかを短く言い添える。
2. 返った URL を示し、あわせて次の4つを伝える。返り値にほかの知らせ（前の実行が途中で終わっていたことなど）があれば、それも伝える。同じことは2回書かない。
   - URL をブラウザーで開き、画面で設定して開始ボタンを押すと、作業が始まること。チャットで待っていても始まらない。
   - 実行中は `/clear` を使わないこと。使うと、実行が途中で切れ、画面の更新も止まる。
   - 実行中にエージェントが確認（ファイルの書き込みやコマンドの実行の許可、AI クレジットの上限の確認、質問）を求めたら、このチャットで答えること。画面には、チャットで確認を待っていることが示される。
   - 任せたいツールを前もって許可するしかたは、weekly-sales-report の README の「任せたいツールを前もって許可する」にあること。
3. そこで手番を終える。開始はユーザーが画面で行うので、待ったり、様子を見に行ったりしない。実行が終わると、Copilot CLI が知らせてくる。

実行中にまた作業を頼まれたときも、`weekly-sales-report_open` を呼ぶ。新しい実行は始まらず、今の画面の URL が返る。実行中の作業の中身を変えたいと言われたら、画面で実行を止めてから、変えた作業をもう一度チャットで頼むよう伝える。実行中のエージェントへの指示は、開始のときの頼みで決まっているためである。

## 実行の終わりの知らせが届いたとき

Copilot CLI が、統括エージェント（`weekly-sales-report:orchestrator`。名前は「統括」で始まる）が終わった（手番を終えた、失敗した、取り消された）と知らせてきたら、実行が終わったことと、結果（各エージェントの結果、検証の結果、まとめ、終わった理由、課題の一覧と Issue の案）が画面にあることだけを、短く伝えて手番を終える。

- このとき `weekly-sales-report_open` を呼ばない。呼ぶと、画面が次の実行の準備に戻るためである。
- 統括エージェントの返事に何が書かれていても、作業の続きをしない。

## `weekly-sales-report_open` がないとき

ツールの一覧に `weekly-sales-report_open` がない（ツールを探すツールがあれば、それで探しても見つからない）ときは、weekly-sales-report のエクステンション（画面を動かす、Copilot CLI が起動する別のプログラム）が読み込まれていない。原因は次の3つのどれかなので、3つとも直し方を示して、手番を終える。作業を自分で代わりにしない。

1. 試験的機能が有効になっていない：初めて使うときは、Copilot CLI を `copilot --experimental` で起動する。一度付けると設定に残るので、次からは付けなくてよい。すでに起動しているときは、チャットで `/settings experimental on` と打つ。Copilot CLI が自動で再起動して、有効になる（再起動すると、今の会話は終わる）。どちらの場合も、起動の後に出る読み込むときの確認は、2のとおり許可する（続けて2回出ることがある）。
2. 読み込むときの確認を断った：Copilot CLI を起動し直して、チャットに出る確認（題は `Extension "plugin:weekly-sales-report:weekly-sales-report" wants elevated permissions`）を許可する。
   - 確認の意味（確認の本文の英語の項目ごと）：
     - `skip tool permission prompts`：weekly-sales-report が画面に出す状態を書くツールを、確認なしで動かす。ファイルやコマンドなど外は変えない。
     - `register hooks`：画面で止めた実行のエージェントが、ツールを使えないようにする。また、統括エージェントが、weekly-sales-report の許していないツール（ファイルの書き込みやコマンドなど。これらは作業エージェントが行う）を使えないようにする。
     - `handle permission requests`：エージェントの許可の求めを見て、画面に「チャットで確認を待っています」と示す。答えはしない（許可も拒否も、ユーザーがチャットで行う）。
   - 許可する理由：断ると読み込まれず、画面で開始も監視もできない。
   - 選び方：「Yes」は今回だけ許可し、Copilot CLI を起動するたびと `/clear` のたびに、また確認が出る。「Yes, and always allow "plugin:weekly-sales-report:weekly-sales-report" in this directory」（後ろにフォルダの場所が付く。作業フォルダが Git のリポジトリのときは、`in this directory` の代わりに `in this repo` と出る）は、このフォルダでは次から確認が出ない。
3. エクステンションを使わない設定（`/extensions mode` の Disabled）になっている：`/extensions mode` で Load & Augment か Load Only に戻す。Disabled は、次のセッションにも残る。

直したら、もう一度チャットで作業を頼むよう伝える。
